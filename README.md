## 1. Собственная игровая механика

Игра построена на механике риска и накопления добычи.

* Игрок начинает с определённым количеством монет.
* За каждую попытку списывается 1 монета.
* Игрок выбирает одну из трёх шахт:

  * старая шахта - низкий риск и небольшая награда
  * глубокая шахта - средний риск и средняя награда
  * заброшенная шахта - высокий риск и большая награда
* После выбора шахты может произойти одно из событий:

  * найдена руда
  * найден самоцвет
  * шахта оказалась пустой
  * произошёл обвал
  * получена бесплатная попытка
* Найденная добыча сначала накапливается отдельно от основного баланса.
* При обвале вся незабранная добыча теряется.

---

## 2. Собственный геймплей (логика игры)

Игрок самостоятельно выбирает уровень риска и решает, когда закончить экспедицию.

* Каждая шахта имеет собственные вероятности игровых событий.
* Чем опаснее шахта, тем выше шанс получить крупную награду.
* После успешной добычи игрок может:

  * продолжить играть и попытаться увеличить выигрыш
  * забрать накопленную добычу
* Забранная добыча добавляется к основному балансу.
* При обвале накопленная добыча обнуляется.
* Событие бесплатной попытки позволяет сделать следующий ход без списания монеты.
* Игра продолжается, пока у игрока остаются средства для новых попыток.

## 3. Использование паттерна «Цепочка обязанностей»

Паттерн «Цепочка обязанностей» используется для обработки результатов игрового события.

* После выбора шахты генерируется тип события.
* Полученный запрос передаётся в цепочку обработчиков.
* В цепочке используются обработчики:

  * `OreHandler` - обработка найденной руды
  * `GemHandler` - обработка найденного самоцвета
  * `EmptyHandler` - обработка пустой попытки
  * `CollapseHandler` - обработка обвала
  * `LuckyHandler` - обработка бесплатного хода
* Каждый обработчик проверяет, относится ли запрос к нему.
* Если обработчик не может обработать событие, запрос передаётся следующему элементу цепочки.
* Контроллер не содержит отдельную логику для каждого результата игры.
* Добавление нового события возможно через создание нового обработчика без изменения основной структуры программы.

Использование паттерна позволяет отделить генерацию игровых событий от их обработки и сделать игровую логику более гибкой.
